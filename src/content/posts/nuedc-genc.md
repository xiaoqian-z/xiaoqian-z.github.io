#### M0资源分配

由于MSPM0G3507相当于STM32中的F103C8T6芯片，芯片可用资源相当的少，所以需要分配好资源，简化代码，首先得收集M0的信息

需要时刻记录代码内存的占用情况，以便按需求删减代码，因此需要有通过keil编译后数据结算出Flash和SRAM的占用情况

例如(最开始逐飞点灯的程序):

Programmer Size: Code=18436 R0-data=1264 Rn-data=208 ZI-data=5520

| Name    | Translation | Where |                                           Date |
| :------ | :---------: | :---: | ---------------------------------------------: |
| code    |             | Flash |                    C/C++ ->Machine Instruction |
| RO-date |  Read Only  | Flash |                            Constant eg:"Hello" |
| RW-date | Read-Write  | F+RAM |    global/static variables with initial values |
| ZI-date |  Zero-Init  |  RAM  | global/static variables without initial values |

由此可知: Flash=18436+1264+208=19908，接近19kB，利用率**14.8%**

RAM=208+5520=5728，接近5kB，利用率**15.6%**(百分比往往比数据更加直观)

# 总结

最终结果出来了，是省三等奖，挺可惜的，算一个参与将吧

比赛前：准备的很充足，硬件基础非常好，有天猛星拓展版，有两块，分为新和旧，有步进驱动TMC2209和AS5600，还有8701电机驱动，灰度循迹模块，视觉模块K230，准备了很多车模，有购买的，也有3D打印的。也完成了很多题目，最简单的是24H题，随便几个模块就可以完成了，不过我完成的非常勉强，个人觉得调节的非常不稳定，只使用了一些并联的PID环很难使用，循迹非常卡顿，不过赛题非常简单，使用了组合模块陀螺仪旋转指定角度就完成了，后面合作完成这道题时使用了陀螺仪全局惯导以及三串来调节大车，行驶过程非常稳定，**三串**就是误差环——角速度环-速度环，每一个环的输出直接作为下一个环的输入，这样调节起来非常稳定，同时修改了直线、转弯、循迹的逻辑，直线就是把红外输入的误差保持为0，转弯就是把误差保持为一个固定的值，它们都是特殊情况的循迹，这样大大简化了代码，减少了调节的参数，化繁为简。代码方面由于过于使用AI导致代码无法看懂，同时使用CODEX思考的时间非常长，花了很多时间最终做出了令人难受的代码，最后让胡来帮我完成代码框架

赛题出来时：确认了只有C,E,H题适合我们完成，然后再E和H题之间纠结，E题我有龙门架结构，所以对于我们最难的部分是视觉，可是写字机放在212，而我们的场地在203，然后又不得不回去拿，但是进不去，然后找了两个人，都是在里面的队伍，最后苏帮我拿了出来，可惜决定在11；30之前必须要确定选题，我不愿意完全拆掉重组导致无法取出错位的螺丝，同时也是螺丝刀不够，最终导致心态不好选择了H题，如果选择E题确实学不到什么东西，但是很大概率那省一，不后悔吧

赛时：重新使用手写代码，但是胡却过于使用AI，最终他也不得不修理代码，我出时间在写报告上面，同时少量参与代码修正，参考AI同时自己手写代码，同时参与参数的记录以及修改，小车的结构部分都是他们完善的，同时视觉部分也是，最后包装时间还是有些手忙脚乱的，一方面指导老师一直在提出一些需求，我需要不停的修改报告，然而老师提出来的要求是好的，但是根本不切合实际，例如把用到模块的原理图全部放到文章的内容里面，就一直叫我把拓展版的原理图放在报告里面，这种就根本没有必要，都只是引出了一些接口以及按键LED灯以及蜂鸣器什么的，对于专业的人来说根本就是没有实际意义的内容，最后我只是把防反接电路单独放了进去，有些必要的时红外循迹模块的电路，然后还有一些离谱的要求，例如有些表格经常出现在页首，由于前面一页放不下去，所以会出现前面一页有大面积空白的情况，然后老师就认为这样不行，就必须删减内容，但是真的很难缩减了，报告经常出现图片和文字重叠的情况，由于不熟悉使用WPS导致无法解决这个问题，最后用一些奇怪的方法解决了，就把图片放在标题中间就可以出现。封箱阶段由于我真的不想花没有必要的钱，没有买泡沫，最后是胡买了一些泡泡纸来作为缓冲，不过真的一点都不够，我们的车模尺寸刚好和箱子的高一样，但是老师说要保持箱子正面朝上，最后不得不强行挤压小车，最终摄像头的3D打印件弯曲，导致最后无法拿分。为了提高识别的帧率，视觉方面只让K230识别中间一块很小的区域

测评阶段：到是没有说的那么严格，基本上有20分钟的准备时间，同时还有20分钟的测试时间，一个房间有四个场地，不过只有四位老师，所以说两组队伍准备的时候，两组队伍就测试，两个老师测试一支队伍，测试一个要求以后可以稍微对小车进行调参，可以调整测试要求的顺序，由于看到摄像头已经压弯了，不仅看到的范围变小了，同时识别的区域也错位了，3D打印件后面根本无法掰，最后在那20分钟里面做了很久才能让摄像头勉强识别到小球，处于多方面考虑，由于听说之前测试完成的队伍说只要完成了要求五就可以不用测试要求四，我们选择直接跳跃到要求五，毕竟只要完成这个就可以拿到两问的分数，结果没有想到在运行到99%时摄像头突然没有识别了，然后0分，再进行要求四要求三的时候都没有拿分更不用说要求六了，最后只拿到了要求一、二的分数

最后结果没有想到还是有省三的名次，也许是报告加分了，也许只是参与了就已经超过了很多队伍
